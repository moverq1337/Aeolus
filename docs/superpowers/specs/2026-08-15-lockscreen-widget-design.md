# Aeolus v1.1 — Lock Screen widget: дизайн-спецификация

Дата: 2026-08-15
Автор: moverq1337
База: спека v1 `2026-08-14-aeolus-design.md`; исследование SkyLight (4 агента,
исходники Lakr233/SkyLightWindow, boring.notch, mew-notch, Atoll + эксперименты
на macOS 26.5).

## 1. Что строим

Виджет Now Playing на экране блокировки macOS: отдельная чёрная карточка
между часами и стопкой «аватар → пароль» — не остров. Показывается, пока
существует медиа-сессия (играет или на паузе). Кнопки работают до
аутентификации (подтверждено: интерактивные виджеты Alcove/Atoll).

Не строим: другие локскрин-виджеты (погода, батарея, календарь), показ
острова на локскрине, заставку (screensaver).

## 2. UX

### 2.1 Карточка (360×140 — финал после итераций с владельцем, 2026-08-15)

Компактная карточка, верх — как лайв-активити, кнопки снизу по центру.
- Фон: чёрный, opacity 0.85, без блюра; скругление 24pt; без рамки.
- Верхний ряд: обложка 64×64 (скругление 10pt), колонка: название
  (SF 14 bold, белый, 1 строка), исполнитель (SF 12, белый 55%, 1 строка),
  тонкий прогресс-бар (только отображение; скрыт для live-стримов).
- Нижний ряд по центру: backward.fill / play-pause / forward.fill — те же
  `ControlButton` и размеры, что в раскрытом острове (16 / 24 / 16).
- Тёмная тема форсирована. `sharingType = .none` — виджет не попадает
  в записи экрана.

### 2.2 Позиция (правка по фидбеку владельца, 2026-08-15)

- Горизонталь: центр экрана.
- Вертикаль: карточка прибита вниз — нижний край на 240pt от низа экрана
  (прямо над зоной аватара/пароля), `userOffset` только поднимает:
  слайдер 0…+320pt, шаг 10.
- Жёсткий кламп: нижний край карточки всегда ≥ 220pt от низа экрана
  (защита от класса багов Alcove #555: виджет закрыл список юзеров).
- Только встроенный экран (как и остров); внешние — вне скоупа v1.1.

### 2.3 Анимации и живость

- Появление (блокировка подтверждена): fade 0→1 + scale 0.96→1,
  пружина открытия `.spring(response: 0.42, dampingFraction: 0.8)`.
- Исчезновение (разблокировка подтверждена): выдержка 150 мс
  (анти-мерцание на кроссфейде разблокировки — проверенная константа
  boring.notch), затем мгновенный `orderOut`, без анимации.
- Стрим адаптера при блокировке НЕ глушится (глушится только на сон,
  как в v1) — смена трека/паузы обновляет карточку вживую.
- Прогресс: `TimelineView(.animation(minimumInterval: 0.5, paused:))` —
  пауза, когда не играет или карточка скрыта.

## 3. Архитектура

### 3.1 Модуль `Aeolus/LockScreen/`

```
SkyLightSpace.swift        обёртка приватного SkyLight (см. 3.2)
LockWidgetController.swift панель + конечный автомат блокировки (см. 3.3)
LockWidgetView.swift       SwiftUI-карточка (читает NowPlayingStore, MediaActions)
```

Плюс общий хелпер `Aeolus/Private/PrivateSymbols.swift` (см. 3.5).

### 3.2 SkyLightSpace — механика (из исходников SkyLightWindow/mew-notch)

Failable-синглтон. dlopen
`/System/Library/PrivateFrameworks/SkyLight.framework/Versions/A/SkyLight`
(RTLD_NOW), каждый символ через guard-let dlsym → `@convention(c)`-указатель:

- `SLSMainConnectionID() -> Int32`
- `SLSSpaceCreate(cid, 1, 0) -> Int32`
- `SLSSpaceSetAbsoluteLevel(cid, sid, 400)` — ровно 400
  (kSLSSpaceAbsoluteLevelNotificationCenterAtScreenLock). Проверено на
  этой машине: значения > 700 клампятся к 700 и на локскрине НЕ рисуются;
  400 — единственное полевое значение (SkyLightWindow, mew-notch, Atoll).
- `SLSShowSpaces(cid, [sid])`
- `SLSSpaceAddWindowsAndRemoveFromSpaces(cid, sid, [windowNumber], 7)` —
  делегирование окна (вызывается один раз; снимает окно со всех прочих
  пространств — поэтому в это пространство идёт ТОЛЬКО выделенная панель
  виджета, никогда панель острова).

Любой отсутствующий символ → синглтон nil → фича недоступна.

### 3.3 LockWidgetController — панель и конечный автомат

Панель: `NSPanel [.borderless, .nonactivatingPanel]`,
`canBecomeKey/Main = false`, `isOpaque = false`, `backgroundColor = .clear`,
`hasShadow = false`, мышь включена (кнопки), размер строго 360×140.
Создаётся ОДИН раз при включении настройки (или на старте, если включена),
делегируется в 400-пространство один раз, дальше только
`orderFrontRegardless()` / `orderOut()`. Пересоздание в цикле блокировки
запрещено (быстрые циклы create/destroy пространств опасны для WindowServer).

Конечный автомат (чистый редьюсер, TDD):

- Входы: `screenIsLocked` / `screenIsUnlocked` (существующий
  SystemObservers), `didWake`, тик сверки.
- События — лишь триггеры. Истина — публичный
  `CGSessionCopyCurrentDictionary()`:
  - `CGSSessionScreenIsLocked` == 1 → заблокировано;
  - `kCGSSessionOnConsoleKey` != 1 → чужая сессия (fast user switching) —
    рисовать НЕЛЬЗЯ.
  Причина: `screenIsLocked` прилетает уже при старте заставки (openradar
  26264008), `screenIsUnlocked` после Touch ID иногда опаздывает.
- Сверка коротким окном: после каждого события — опрос каждые 500 мс
  максимум 5 с, затем тишина. Ноль поллинга в простое (инвариант v1 §6).
- Показ разрешён только при: настройка вкл ∧ заблокировано ∧ on-console ∧
  есть медиа-сессия ∧ SkyLightSpace доступен.

### 3.4 Поток данных

Без изменений: карточка читает те же `NowPlayingStore` (@Observable) и
`MediaActions`, что и остров. Никаких новых источников.

### 3.5 Попутный фикс: NotchSpace (бомба в v1)

`NotchSpace.swift` сегодня объявляет CGS-функции через `@_silgen_name` и
лишь потом проверяет dlsym — но `@_silgen_name` создаёт жёсткую ссылку,
которую dyld биндит на старте: исчезни символ в будущей macOS — приложение
умирает до запуска guard. Мигрируем на dlsym-указатели через общий
`PrivateSymbols.load(framework:symbol:)`; NotchSpace и SkyLightSpace
используют один хелпер. Поведение неизменно, падение заменено деградацией.

## 4. Настройки

- Toggle «Lock Screen widget» — default **false** (приватный SPI на
  поверхности безопасности — только осознанный опт-ин; так же у
  boring.notch и mew-notch).
- Slider «Raise widget» 0…+320pt (виден/активен только при вкл. тумблере).
- При недоступности SPI: строка «Lock Screen widget — unavailable on this
  macOS», тумблер задизейблен.
- Ключи: `lockScreenWidget` (Bool, false), `lockScreenOffset` (Double, 0).

## 5. Иерархия отказов

1. Символы не нашлись → фичи нет, остальное приложение не затронуто.
2. Пространство не создалось / показ не сработал → панель невидима,
   без ретраев в цикле.
3. Настройка выключена → модуль не инициализируется, ноль приватных вызовов.
4. Смерть процесса (`pkill -x Aeolus`) → WindowServer уничтожает окна и
   пространства процесса → стоковый локскрин. Это и есть путь спасения.

## 6. Тестирование

**Юнит (TDD):** редьюсер конечного автомата (все комбинации событий ×
состояний сессии, включая FUS и запаздывающий unlock); кламп позиции
(offset крайние значения, нижний зазор ≥ 220pt на разных высотах экрана);
graceful nil хелпера символов.

**Ручной протокол (обязателен до мерджа в main):**
1. До первого теста: `sudo systemsetup -setremotelogin on`; со второго
   устройства проверить `ssh moverq@<mac>.local` и команду спасения
   `pkill -x Aeolus`.
2. Пути блокировки: Ctrl+Cmd+Q; закрытие крышки; засыпание дисплея;
   заставка.
3. Пути разблокировки: пароль; Touch ID (проверить отсутствие «лишней
   секунды» виджета и мерцания).
4. Кнопки: play/pause/next с локскрина реально управляют музыкой; клики
   мимо карточки уходят системе; поле пароля сохраняет фокус ввода.
5. Fast user switching: виджет не появляется в чужой сессии.
6. Без музыки: локскрин девственно чист.
7. Выключение тумблера при заблокированном… недостижимо (настройки
   недоступны при блокировке) — выключение применяется к следующей
   блокировке.

**QUALITY.md** дополняется этим протоколом.

## 7. Риски

| Риск | Митигция |
|---|---|
| Apple меняет/удаляет SLS-символы | dlsym-guard всюду, деградация в «фичи нет»; фикс NotchSpace убирает падение на старте |
| Уровень 400 меняет семантику в новой macOS | ручной протокол на бетах; выключатель по умолчанию off ограничивает радиус поражения |
| Перекрытие уведомлений локскрина (они тоже уровень 400) | наша позиция — центр, баннеры — верхний правый угол; пересечений нет |
| Клики-перехваты над паролем (класс Alcove #555) | кламп ≥ 220pt от низа, панель по размеру контента, canBecomeKey=false |
| Залипание виджета после разблокировки | сверка CGSession + окно поллинга 5 с |
